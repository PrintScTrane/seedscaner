# Seed Scanner — Minecraft 26.2 / Fabric

주변에서 클라이언트가 받은 청크의 구조물과 던전 정보를 수집하고, 필요한 정보가 모이면 자동으로 시드를 계산하는 클라이언트 모드입니다. SeedCrackerX 2.16.1을 기반으로 자동 저장·복원, 초기화 명령, 한국어 HUD를 추가했습니다.

## 설치

1. Minecraft Java Edition **26.2**에 **Fabric Loader 0.19.3 이상**을 설치합니다.
2. 배포된 `seed-scanner-1.0.0+26.2.jar`를 해당 게임 인스턴스의 `mods` 폴더에 넣습니다.
3. 기존 SeedCrackerX는 제거합니다. 같은 모드 ID를 사용하므로 둘을 함께 설치하지 않습니다.
4. **Java 25**로 실행합니다. 필요한 Fabric API 모듈과 Cloth Config는 JAR에 포함됩니다. 다른 모드 때문에 Fabric API를 별도로 설치한다면 26.2용을 사용합니다.

월드나 서버에 들어가면 스캔과 기록 복원이 자동으로 시작됩니다. 다시 접속해도 발견한 구조물·던전·엔드 기둥과 스캔 완료 청크, 확정된 시드는 유지됩니다.

## 명령어

| 명령어 | 동작 |
|---|---|
| `/seedscan` 또는 `/seedscan status` | 스캔·수집·연산 상태와 발견한 시드 표시 |
| `/seedscan reset` | 현재 월드의 저장 기록과 결과를 초기화하고, 받은 주변 청크부터 다시 스캔 |
| `/seedscan rescan` | 발견 기록을 유지하면서 받은 주변 청크 재검사 |
| `/seedscan hud on` / `/seedscan hud off` | HUD 표시 / 숨기기 |
| `/seedscan pause` | 새 청크의 스캔 접수 중지. 이미 시작한 작업은 완료됩니다. |
| `/seedscan resume` | 새 청크 스캔 재개 및 주변 재검사 |
| `/seedcracker gui` | 기존 엔진의 탐지 설정 화면 |

`/seedcracker data clear`도 현재 월드의 새 저장 기록을 초기화합니다. 기존 upstream의 `data restore`는 구형 텍스트 기록을 가져오는 기능이며, 새 JSON 기록은 접속 시 자동 복원됩니다.

## 화면의 진행률

- **청크 스캔**: 저장된 완료 청크와 현재 스캔 대기 중인 청크를 기준으로 처리율을 표시합니다. 이동하여 새 청크를 받으면 비율이 내려갈 수 있습니다. 스캔 오류는 완료로 기록하지 않습니다.
- **정보 수집**: 오버월드는 리프팅 정보 40비트와 일반 정보 32비트가 모두 필요합니다. 엔드 기둥 정보를 얻은 경우 일반 정보 32비트 기준을 표시합니다. 구조물 종류마다 제공하는 비트 수가 다릅니다.
- **연산**: 현재 계산 단계에서 실제로 검사한 후보 수의 비율입니다. 단계가 바뀌면 0%부터 시작합니다. 100%는 해당 단계가 끝났다는 뜻이며, 추가 정보가 필요할 수 있습니다.
- **월드 시드**: 후보가 하나로 확정되면 숫자가 표시되고 저장됩니다.

난파선, 사막 사원, 이글루, 정글 사원, 마녀 오두막 등 다양한 구조물이 있는 곳을 탐색하세요. 한 자리에서 기다리기만 하면 충분한 정보가 모이지 않을 수 있습니다. 클라이언트가 받지 않은 먼 청크는 스캔할 수 없습니다. 서버가 숨기는 블록이나 변형된 월드 생성 방식은 정확한 탐지를 방해할 수 있습니다.

## 저장과 복구

- 저장 위치: 게임 인스턴스의 `config/seed-scanner/worlds/<월드식별자>.json`
- 저장 주기: 게임 중 약 5초마다, 그리고 접속 종료 시. 임시 파일 작성 후 교체하여 저장합니다.
- 월드 식별자는 싱글플레이 저장 경로 또는 서버 주소와 서버가 보낸 시드 해시를 사용합니다. 서버가 주소나 해시를 바꾸면 별도의 기록으로 취급됩니다.
- 강제 종료 직전 최대 약 5초의 기록은 저장되지 않을 수 있습니다.
- 재접속하면 수집 기록으로 연산을 다시 시작합니다. 실행 중이던 연산의 CPU 위치까지 저장하는 방식은 아닙니다.
- 파일이 손상되면 원본을 덮어쓰지 않고 오류를 표시합니다. `/seedscan reset`으로 새로 시작할 수 있습니다.

연산 시간은 수집한 정보와 CPU에 따라 달라지며, 모든 월드에서 시드 발견을 보장하지 않습니다. 기존 엔진은 바닐라와 호환되는 생성 규칙을 가정합니다.

## 소스 빌드와 검증

Java 25를 설치하고 프로젝트 폴더에서 `gradlew.bat build`를 실행합니다. 결과는 `build/libs`에 생성됩니다. `scannerChecks` 검증도 build에 포함됩니다.

검증 범위: 저장·복원, 64비트 시드 보존, 초기화 후 재로드, 손상 파일 보존, 월드/차원 분리, 청크 중복 방지, 병렬 카운터, 연산 처리율. 실제 게임 플레이에서의 시드 발견은 별도 검증이 필요합니다.
